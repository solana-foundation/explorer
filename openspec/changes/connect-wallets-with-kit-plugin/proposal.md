# Proposal: Connect wallets through the Kit wallet plugin instead of Solana Wallet Adapter

## Context

- **Two high-severity advisories with no fix.** Dependabot [#457](https://github.com/solana-foundation/explorer/security/dependabot/457) and [#458](https://github.com/solana-foundation/explorer/security/dependabot/458) report denial-of-service parsers in `image-size` at `runtime` scope, with `first_patched_version: null`. `pnpm why image-size` shows exactly one runtime path: `@solana/wallet-adapter-react` → `@solana-mobile/wallet-adapter-mobile` → `react-native` (peer) → `metro` → `image-size`. Explorer is a web app; it pulls a React Native toolchain into its production dependency graph solely to satisfy wallet-adapter's mobile wallet support. With no upstream patch available, removing wallet-adapter is the only way to clear the runtime exposure.
- **Small blast radius.** Wallet state is not global. `WalletProvider` is mounted at exactly one place — `app/features/idl/ui/IdlSection.tsx` — and consumed by five modules inside `app/features/idl/interactive-idl/`. The root layout has no wallet provider.
- **Kit 7 already landed.** PR #1193 moved the repo to `@solana/kit` 7.0.0, which is what makes `@solana/react` and `@solana/kit-plugin-wallet` installable today.
- **The migration plan sequences this later.** `Phase 6.4` of the internal web3.js→kit plan puts the wallet swap behind the Anchor rework (6.1) and kit-native transaction building (6.3). The advisories make waiting unattractive, so this change decouples the wallet layer from that ordering.

## Why

We want the vulnerable React Native dependency chain out of the production graph now, without waiting for the Anchor and transaction-building work that Phase 6 sequences ahead of the wallet swap.

Principles that drove the scope:

- **Replace the connection layer, not the transaction layer.** Wallet discovery, connection, and signing are what pull in wallet-adapter. Transaction *building* and *broadcasting* do not. Keeping the existing web3.js build-and-send path confines this change to the wallet seam and leaves Phase 6.1/6.3 to do their own work on their own schedule.
- **Wallet Standard discovery replaces per-wallet adapters.** Modern wallets register themselves via Wallet Standard, which is what `@solana/kit-plugin-wallet` consumes. Explorer already passed `wallets={[]}` to wallet-adapter to rely on autodetection. Unlike wallet-adapter, discovery is now filtered by the client's chain, so a wallet that does not advertise a given chain is not offered there.
- **The seam should be obvious and deletable.** The bridge between Kit signers and web3.js transactions is one named module, and the compat hook keeps its consumers on one import. Phase 6.3 deletes both rather than untangling them.

Alternatives considered:

- **Pin or override `image-size` to a patched version.** Rejected: there is no patched version. The advisory covers `<= 2.0.2`, which is every published release.
- **Wait for Phase 6.1/6.3 and migrate the whole interactive-IDL stack at once.** Rejected: that is a multi-PR rewrite of Anchor-driven transaction building, and the runtime advisories stay open for its duration.
- **Migrate execution to Kit as part of this change** (`solanaRpc` plugin, `client.sendTransaction`, Kit confirmation). Rejected for this PR: it rewrites the error taxonomy that `use-execute-transaction.ts` and its tests depend on (`SendTransactionError`, `pre_broadcast_failed` vs `broadcast_failed`) and duplicates Phase 6.3's scope. The bridge added here is the smaller, reversible step.
- **Use the Wallet Standard hooks that ship inside `@solana/react`** (`useWalletAccountTransactionSigner` and friends). Rejected: upstream marks them as superseded by the wallet-plugin hooks and slated for deprecation, so adopting them would mean migrating twice.

## What Changes

- **Dependencies.** `@solana/wallet-adapter-base`, `-base-ui`, `-react`, and `-react-ui` are removed. `@solana/react` 7.0.0 and `@solana/kit-plugin-wallet` 0.14.0 are added. `@solana/kit` stays at 7.0.0 — `@solana/react` 7.0.0 peers that exact version. The lockfile loses the entire `react-native`/`metro`/Babel subtree that came with the mobile wallet adapter.
- **`disposablestack` is added** and imported by the wallet provider. `@solana/plugin-core` registers plugin cleanup through `DisposableStack`, a 2025-era platform global that Next.js does not polyfill; without it the interactive-IDL section throws on browsers older than Chrome/Edge 134, Firefox 134, or Safari 18.4. The `auto` entry point installs the global only where it is missing.
- **`app/providers/wallet-provider.tsx`** builds a Kit client with `walletSigner({ autoConnect, chain, storageKey })` and publishes it through `ClientProvider` from `@solana/react`, replacing `ConnectionProvider` → `WalletProvider` → `WalletModalProvider`. Clients are cached per chain, since each one runs its own Wallet Standard discovery and silent reconnect; the cache is bounded by the number of chains the mapping can return and is held for the life of the page rather than disposed, because disposing a client would defeat the reconnect it exists to preserve. Each chain gets its own `storageKey` so a wallet connected on one cluster does not appear connected on another. The `@solana/wallet-adapter-react-ui/styles.css` import is dropped; no repo CSS selects `.wallet-adapter-*`.
- **`app/providers/wallet/cluster-chain.ts`** maps a `Cluster` to a Wallet Standard chain identifier. The identifier is not only a discovery filter — `modifyAndSignTransactions` sends it with every `signTransaction` request, and wallets use it to decide which network to simulate the transaction against. Custom and SIMD-296 point at arbitrary endpoints, so they map to `solana:localnet`; labelling them `solana:mainnet` would make wallets preview against the wrong network and warn about transactions that are fine.
- **`app/providers/wallet/sign-web3js-transaction.ts`** bridges a Kit wallet signer to web3.js transactions by converting through the transaction wire format in both directions — the one representation the two libraries already agree on, and the only one that carries legacy and versioned transactions alike (Anchor's wallet interface, which `UnifiedWallet` implements, is generic over both). Signature slots survive the trip because Kit decodes a zero-filled signature as an unsigned slot, which is exactly how web3.js serializes one. The signed result is rebuilt from the bytes the wallet returned: wallets exposing `solana:signTransaction` surface as `TransactionModifyingSigner`s and may alter the message, so a signature copied back onto the original would not cover what gets broadcast.
- **`app/providers/wallet/use-wallet.ts`** exposes the wallet slice the interactive-IDL modules already consume (`connected`, `connecting`, `publicKey`, `signTransaction`, `signAllTransactions`, plus `connect`/`disconnect`/`walletName`), so `use-instruction.ts`, `use-execute-transaction.ts`, and `InteractInstruction.tsx` change only their import. It reports "no wallet" as `undefined` rather than `null`, so `isEnabled`, `createGetAutocompleteItems`, and `createWalletPrefillDependency` widen their `publicKey` parameter to match — the repo's `unicorn/no-null` direction, and `ExternalDependency.getValue` already allowed it.
- **`app/providers/wallet/WalletPickerDialog.tsx`** replaces `WalletModalProvider`'s modal, listing discovered wallets from `useWallets` in the repo's own dialog primitive.
- **`ConnectWallet.tsx`** drops `useWalletMultiButton`/`useWalletModal` and drives the picker itself, behind a `WalletReadyGate`. Wallet Standard registration is asynchronous, so without the gate a returning user sees an enabled "Select Wallet" during warm-up and clicking it opens a picker claiming no wallet is installed. `BaseConnectWallet` and `BaseConnectWalletButton` are unchanged.
- **`InteractWithIdl.tsx`** reads the analytics wallet label from `walletName` rather than `wallet.adapter.name`.
- **The `skipToast` prop is removed** from `WalletProvider`. The Kit plugin reports failures by rejecting the action promise rather than through an `onError` callback, and the provider's only call site already passed `skipToast`, so no toast was reachable in the app. Connection failures are logged via `Logger.error` at the call site, matching the behaviour users actually saw.

## Impact

- **Affected runtime surface:** the interactive-IDL tab on program pages. Nothing else in Explorer touches wallet state.
- **Security:** `image-size` leaves the runtime dependency graph. It remains reachable at `dev` scope through Storybook's `vite-plugin-storybook-nextjs`, which is build-time only and not shipped to users.
- **Tests.** `app/providers/__tests__/wallet-provider.spec.tsx` is removed — it asserted the `onError`/`skipToast` behaviour that no longer exists. New specs cover the signing bridge (both signer kinds, the sign-and-send-only rejection, and the empty-batch short circuit) and the cluster-to-chain mapping. The two interactive-IDL specs retarget their mocks from `@solana/wallet-adapter-react` to the compat hook.
- **Accepted risk (sign-and-send-only wallets).** A wallet that implements `solana:signAndSendTransaction` but not `solana:signTransaction` cannot be used to execute instructions, because Explorer broadcasts through its own RPC connection and needs the signed transaction back. Such a wallet now gets an explicit error instead of a silent failure. Phase 6.3 removes the constraint by letting the wallet send.
- **Accepted risk (chain identifier on custom clusters).** Custom and SIMD-296 clusters are labelled `solana:localnet`, so a wallet that does not advertise that chain is not offered there. This is the deliberate trade: the identifier reaches the wallet's signature prompt, and claiming `solana:mainnet` would have wallets simulate a custom-endpoint transaction against mainnet and warn about transactions that are fine. Discovery on mainnet, devnet, and testnet is unaffected.
- **Accepted risk (watch-only wallets).** A connected wallet with no signer is reported as not connected, so Execute stays disabled rather than enabling and then failing at signing time. Such a wallet could not have executed instructions under wallet-adapter either.
- **Deferred.** Kit-native transaction building and broadcasting stay with Phase 6.1/6.3; `app/providers/wallet/use-wallet.ts` and `sign-web3js-transaction.ts` are written to be deleted by that work, not extended.
